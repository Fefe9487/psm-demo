# GitHub Pages 自動部署與版本更新

## 未更新的原因

GitHub Pages 原本使用 `gh-pages` 分支，而該分支的互動展示仍是 2026-10-19 建置的程式包。`main` 沒有 Pages 工作流程，後續 PSI／MI 的程式修改不會重新打包。`github-pages` 部署環境原本亦僅允許 `gh-pages`。

## 修正

- 將既有互動展示的打包工具、瀏覽器 Python 轉接層與啟動頁納入 `main`，直接打包同一份 PSM 程式、模板、靜態檔及機制清單。
- `main` 推送後自動跑完整測試、產生 Pages 成品並部署。也支援手動觸發。使用 GitHub Actions 作為 Pages 發布來源，允許 `main` 通過部署環境。
- 每次產生 `version.json`，記錄來源 commit、程式包 SHA-256 與包含啟動頁資源的 `build_id`；服務程式與首頁資源帶版本識別，程式包以不快取請求下載並核對雜湊，避免新舊部署混用。僅修改啟動程式也會產生新版本。
- 首頁會檢查服務程式更新，並核對實際啟動版本後才開放進入。已開啟的填報頁定期檢查新版，只顯示「先儲存，再載入新版」提示，不強制重新整理或清除 IndexedDB。更新連結與深層連結的首頁啟動網址帶版本參數，避免沿用 HTTP 快取中的舊首頁。
- 保留既有瀏覽器資料庫位置，沿用資料庫升級流程。首次開啟深層連結仍可透過 `404.html` 回首頁啟動後返回原頁。
- 保留既有展示的附件編輯修正：更新文件時不重複新增同一筆章節關聯。

## 驗證方式

程式包測試檢查模板變動會改變版本、66 項資料檔確實打包、排除 Python 快取、首頁與服務程式版本一致。轉接層測試操作十四章、案例切換、資料保存、上傳、編輯與重置，並驗證新版 MI 表單及網址前綴。

另以 Chromium 實際執行舊 Pages 的 WebAssembly／Python 程式，保存測試資料，再切換新版成品，檢查 MI 多列與 66 項清單、附件上傳、資料保留、更新提示保留未儲存輸入，以及新瀏覽器直接開啟深層連結。

發布後以 Actions 成功狀態、線上 `version.json` 來源 commit、線上程式包與 MI 畫面確認部署結果。

本機驗證：Pages／轉接層 8 項測試通過；Chromium 的舊版升級、保留資料、實際上傳、保留未儲存輸入及首次深層連結全部通過，無頁面 JavaScript 錯誤。此前完整應用程式回歸 209 項通過，部署工作流程會再驗證含新增測試的完整套件。
