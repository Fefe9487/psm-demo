# PSM 設計原則（內部金科玉律）

本檔只給內部架構用。**不要複製、摘要或連結進需求討論稿**（`2026-08-20-psm-14單元細表-討論稿.md` 及其後續對外版本）。對外仍用「表單／欄位／必送／備查」語言對需求單位。

**階段切分**

- **這一階段**：一般系統。看起來像送審專家系統（主檔、規則開槽、手冊表、申報草案）。先把「同一個安全世界」建出來：實體、掛件、事件日誌、映射表、證據。表單是視圖，不是資料模型。
- **下一階段**：才加入 Agent 協作（監測→判斷→觸發→派工→驗證→關閉）。Agent 必須活在本階段已經定好的同一套安全資訊模型上，不能變成 14 個互不記得的聊天機器人。
- **對人講**：可用時間／空間／物質解釋為何先蒐集三本主檔。不要把 Agent、編排器、十題拷問寫進需求討論稿。
- 教材：[psm-教材-為何先蒐集三個核心.md](./psm-教材-為何先蒐集三個核心.md)
- 逐表三原對照：[psm-三原-14項細表對照.md](./psm-三原-14項細表對照.md)

設計任何模組、以後任何 Agent，用文末十題拷問。

## 零、世界觀：三原交互（時間／空間／物質）

製程安全可以用宇宙學來看：不是三張清單並排，而是**時間、空間、物質**三個原初量，在同一個**次元**裡互相耦合。次元就是甲類場所這個宇宙的框架。危害、防護、義務都從三原的交互長出來；勞工、承攬、稽核、機密是誰能進出這個次元。

對到場所裡的「他」：

| 宇宙學 | 場所 | 主檔 |
|---|---|---|
| 次元 | 這個甲類場所（案件／場所識別） | Case |
| 空間 | 東西在哪：容器、管線、閥、連鎖。P&ID 是空間的圖 | 設備 |
| 時間（運動學） | 物質在空間裡應該怎麼走：連續或批次、開車／正常／停車、上下限 | 製程 |
| 物質 | 佔空間、沿製程移動的東西 | 化學物（CAS） |

另有一條**神聖時間線**（宇宙的世界線）：這個世界實際被改過什麼。登錄、換件、檢查、事故都記一筆。主檔的「現在」是時間線尖端。編排器是唯一寫入口。製程時間 ≠ 神聖時間線：前者是應該怎麼操作，後者是世界被改過什麼。

**三原反應交互**才是一筆安全事實。只有化學名、對不到設備與製程，等於物質沒有度規，只是收集資料。表列必須能指出它碰上了哪一原、哪兩原、或三原同時。

HAZOP 是擾動其中一原、看另外兩原怎麼塌：

- 擾動時間：流量高、溫度低、步驟錯
- 擾動空間：閥失效、破裂、連鎖不動作
- 擾動物質：加錯料、不相容、濃度偏

每個平行世界問：14 項誰沒到位、防護有沒有效；無效就補防護，並寫回主檔，成為時間線上的新事實。

**變動＝三原之一被改。** 時間線記一筆 → 映射拉出掛件 → 用平行世界再檢查交互是否仍安全。

**風險評估不是第四原，是丈量這個宇宙的尺。** 三原在次元裡交互之後，尺才有東西可量；量出來的讀數才是風險等級。尺上的齒有很多、精度不同：HAZOP／FMEA 是粗齒（嚴重度×可能性→等級）；LOPA 是較細的齒（頻率與保護層 PFD，同一筆後果）；QRA 等更細的齒送審通常不強制。沒有三本主檔，等於對空氣比齒。變更、檢查逾期、事故會讓舊讀數過期，要用同一把尺再量，不要另做一把對不到主檔的尺。

它出現的環節：

1. **主要在單元 02**：HAZOP／FMEA 對每個平行世界打嚴重度、可能性、風險等級（定性）。若有 LOPA，對同一筆後果再定量（頻率 × 保護層 PFD）。沒有三本主檔，這一步只是在空表上打分數。
2. **變更時再讀一次（單元 10、07）**：三原之一被改，交互變了，原風險是否仍可接受；PSSR 是物質進入次元前的最後一次確認。
3. **空間保養會改讀數（單元 08）**：防護層檢查逾期，LOPA 用的那層 IPL 不可信，Risk 要重算。表 3.8-9 等的「風險」是這塊空間被物質吃掉的風險，不是另一套 PHA。
4. **塌過之後餵回來（單元 11）**：事故／近失回到單元 02，修正平行世界的可能性或後果。
5. **應變演練依評估選情境（單元 12）**：演練哪一種失控，應對得到 02 裡的後果，不是另寫一套災害。

語義層的 Risk 應是共用物件：HAZOP 寫入、LOPA 加深、MOC／MI／事故讀同一筆。不要另做一個「風險評估模組」自造設備名。

## 一、基本單位是安全資訊，不是表單

表單只是呈現方式。

真正要管理的是：誰、在什麼製程、操作什麼設備、使用什麼物質、產生什麼危害、有哪些保護層、依據什麼程序操作、如何確認其有效、發生什麼變更、變更後是否仍然安全。

優先問：**這筆資料代表什麼安全事實？**  
不要先問：這張表需要幾個欄位？

若一項資訊無法與其他安全資訊產生關係，那多半只是資料收集，不是 PSM。

本階段系統含義：每筆紀錄必須能指向製程、設備、物質、危害、保護層、程序、變更或證據之一；送審表是從這些關係投影出來的。

---

## 二、核心是安全狀態，不是完成率

不要把 PSM 收成：檔有沒有上傳、表有沒有填完、訓練有沒有做、檢查有沒有做。

真正要能回答：**目前這個製程是否仍處於可接受的安全狀態？**

完成一項工作之後，必須能說：它對哪一個製程、設備或危害產生了什麼安全意義。

例如設備檢查不是「檢查完成」一筆紀錄，而應連得上：

設備 → 失效模式 → 保護層 → 檢查項目 → 檢查結果 → 缺失 → 改善 → 再確認。

本階段系統含義：完成率可以當送審輔助指標，不能當唯一門檻。狀態要能從關係圖讀出來（例如保護層檢查逾期、MOC 未關閉、HAZOP 建議未追蹤）。

---

## 三、14 項必須互相咬住

價值在交叉驗證，不在「14 項都做完」。

至少這些關係本階段就要能表達（先做資料連結，不必先做自動推理）：

- 製程安全資訊可被 HAZOP 使用
- HAZOP 能指向 SOP、保護層與檢查要求
- 設備變更觸發 MOC
- MOC 能判斷是否重做 HAZOP 或更新 SOP
- 事故／近失能回到危害辨識與風險評估
- 檢查缺失能反映設備完整性與風險狀態

一個模組若只能做完自己那一項、不知道會影響哪些其他 PSM 資訊，就只是表單模組。

---

## 四、工作是維護安全資訊一致性，不是產生文件

不是「幫使用者產生 HAZOP」，而是：

- 這次 HAZOP 是否與目前製程安全資訊一致？
- 發現的保護層，設備資料裡是否存在？
- SOP 是否真的描述這個操作？
- 檢查計畫是否涵蓋這個保護層？
- 訓練內容是否包含這項操作？

價值在：**建立、維護與驗證**安全資訊之間的邏輯一致性。

本階段系統含義：寫入時就要存關係與來源；報告／Word／PDF 是匯出，不是主檔。

---

## 五、不應只被動存檔，應能分析影響（系統先做，Agent 後做）

傳統：使用者填資料 → 系統儲存。

目標：使用者更新資料 → 分析影響 → 找出需重檢的資訊 → 派發任務 → 追蹤結果。

生命週期：**監測 → 判斷 → 觸發 → 派工 → 驗證 → 關閉**

例：設備 A-101 更換安全閥，不能只留「已完成設備變更」，而要能走出：是否涉及安全功能 → MOC → 是否影響 HAZOP／SOP／再檢查／再訓練 → 相關資訊是否都已更新。

本階段：先把變更當成一等實體、把影響清單當成可儲存的結構。自動派工與 Agent 推理放下一階段。

---

## 六、以後 Agent 小而專，但不能彼此失憶

可有 HAZOP、MOC、機械完整性、SOP、事故、訓練等職責分工。

不能變成 14 個獨立聊天機器人。

**Agent 可以不同，世界只能有一個。**

同一設備不能在設備模組叫 A-101、在 HAZOP 變成 Tank-03、在 MOC 變成「反應槽」。必須指向同一個安全實體。

本階段就把全域 ID 與主檔定死。下一階段 Agent 只准引用這些 ID。

---

## 七、核心能力是影響分析（Impact Analysis）

安全資訊一變，第一個問題不是「這個模組要做什麼」，而是：**這個變化會影響什麼？**

例：原料變更可能影響危害、製程條件、設備材質、HAZOP、SDS、SOP、PPE、緊急應變、訓練、檢查項目。

真正有價值的往往不是「AI 生成」，而是 Impact Analysis。資料模型對了，Agent 能力才長得出來。

本階段：定義影響邊（什麼實體變更會連到哪些實體）。下一階段：沿邊自動展開並派工。

---

## 八、所有判斷都要能追溯（Evidence Chain）

PSM 是安全管理，不是創作。

「這個設備存在高壓洩漏風險」不能只給結論，至少要能指到：哪筆製程、哪項設備、哪個危害、哪個 HAZOP 節點、哪個歷史事件、哪個規範或程序、哪個專家判斷。

AI 可以推論，不能讓推論變成沒有來源的神諭。本階段一般系統寫入的每一條安全結論同樣要有證據鏈；下一階段 Agent 結論不得例外。

---

## 九、不取代責任，只管理人的注意力

目的不是「AI 幫你做完 PSM」，而是 **幫人找出真正需要注意的地方**。

五千台設備不可能每天全看。系統應能指出：哪些設備最近異常、哪些保護層檢查逾期、這次 MOC 可能影響哪些 HAZOP 節點、哪份 SOP 與目前設備配置不一致。

把人的注意力從整理資料，轉到安全決策。本階段先能列出「不一致／逾期／未關閉變更」；下一階段再由 Agent 主動推送。

---

## 十題拷問（設計模組或以後設計 Agent 都用）

1. 它管理的是安全資訊，還是只在填表？
2. 它知道資料屬於哪個製程、設備、物質或危害嗎？
3. 能不能與其他 PSM 資訊建立關係？
4. 能不能發現資料之間的不一致？
5. 資料改變時，能不能判斷誰會受到影響？
6. 能不能觸發其他流程或（下一階段）其他 Agent？
7. 結論能不能追溯到 Evidence？
8. 它在維護安全狀態，還是文件完成率？
9. 能不能主動發現需要人注意的事？
10. 如果把 AI 拿掉，剩下的是有價值的 PSM 資訊模型，還是一堆表單？

第 10 題是本階段的硬門檻：**沒有 AI 也要站得住的安全資訊模型。**

---

## 十一、SDS 是參照庫，不是第四核心

化學品核心資料表仍是「同一化學品代號在同一製程的角色」（化學品代號＋製程編號；化學品代號即 CAS No.）。安全資料表另建 SDS 資料庫，以 SDS 代號為主鍵；化學品列選取 SDS 代號，化學品代號必須三方一致。

不要把 SDS 當成第四份核心資料表，也不要在每一個製程列重複上傳同一份檔。同一甲苯在儲槽與裝卸兩列，應連同一個現況 SDS 代號。
