# 石化及化學工廠 PSM 線上風險評估｜開站 SPEC

- 對齊手冊：`docs/2026-08-21-石化及化學工廠製程安全管理線上風險評估參考手冊草案.md`（第一次填報規格。系統架構以本 SPEC 為準；手冊對規則引擎寫含蓄，本檔寫死行為）
- 性質：給實作 AI／工程的資料與檢核規格。手冊給填報人員及審查，不寫系統架構；本檔才是表、鍵、檢核、提示。語意與手冊一致，體裁不同。欄位英文名可改，語意不可改。
- 資料庫：關聯式。畫面 JOIN 顯示名稱；子表禁止複製父表名稱。
- 畫面用詞：製程安全管理十四項用單元名稱（製程安全資訊、製程危害控制措施…），**不要**對使用者寫「附表一…十四」。審查辦法**附件一**（十二項）可以用。

**交給後續 AI 時，請連同本檔，並加上：**只實作本 SPEC 已列之表、鍵、枚舉與檢核；不得另造運輸表或另列核心資料表（SDS 資料庫、代號表、對應表都不是第四份核心資料表）；不得讓 HAZOP／細表自由輸入設備名、品名、課室名；化學品表禁止存 SDS 檔，必須經代號表連 SDS 代號；提示不得代填嚴重度／可能性，不得自動停機。

## 0. 目標與非目標

### 0.1 設計構想（實作必須照這個理解）

十四項仍是十四項，**不是**把十四項解構成三張表。先建製程、設備、化學品三張核心表當共用索引；引導填完製程－設備－化學品對應表，完成製程安全資訊；再用規則依**既有列**提示。後面各項只能勾已有編號。

| | 傳統填報 | 本系統 |
|---|---|---|
| 完成條件 | 十四份文件齊了 | 十四項指向同一套現場編號 |
| 名稱 | 各表可各寫各的 | 只能選製程／設備／化學品代號 |
| 評估 | 人手打設備名、品名 | 先選製程，再選該製程已建且已對應之設備與化學品 |
| 風險數字 | 人填（或各表各算） | **仍由小組填**；程式只提示該討論什麼 |

優點：把人最容易錯的抽象關聯（這張表叫什麼、那張表叫什麼、對不對得到現場）改由編號與規則勾稽。  
缺點／後續：完整專家規則（物質 × 製程條件 × 材質）要持續編寫，屬後續投資，開站與 demo **只做少數寫死規則證明路徑**，不算裂化速度。

三張核心表是資料整理方式，**不取代**附件一原列十二項及法定應檢附內容。

提示時機：

1. **製程危害控制措施（PHA）**：依對應表＋危害說明，提示偏離、不相容、殘留、引入前檢查、旁通等應討論事項。
2. **機械完整性（MI）**：同一列提示材質、殘留、不相容；得註明可對照本署劣化機制查詢資料庫。開站不連該庫、**不計算裂化或腐蝕速度**、不代評分。

人員可確認、修正或敘明不適用（理由必留）。提示**不**寫入嚴重度、可能性、風險等級，**不**下達停機。

### 0.2 目標（開站／demo）

1. 先建核心資料表，並同期蒐集送審第二章（附件一）安全衛生管理基本資料與圖資結構化登錄；填完對應表後，才允許製程危害控制措施評分。
2. HAZOP：先選製程，再只選該製程下、且出現在對應表（或該設備已聲明無製程化學品）之設備與化學品代號（`chemical_code`）。
3. 圖檔可上傳；納管以結構化欄位為準。管理計畫、規章、制度開站只上傳附件，不拆全文。
4. Demo 至少跑通一條寫死提示：碳鋼＋氯化氫（H314）＋可能殘留 → PHA／MI 列出「材質條件不相容；停車未排淨」，S／L 仍空白待小組填。

### 0.3 非目標（本階段禁止當完成條件）

- 把十四項收成三張法定表，或宣稱取代附件一十二項
- 專家規則全集、裂化／腐蝕速度計算、自動推論嚴重度或可能性
- Agent 自動推論、自動派工、自動停機、自動結案
- 以完成率代替安全狀態
- 未接入製程之過境車輛評分
- 以劣化資料庫分數取代製程危害控制措施之風險讀數
- OCR 自動把 P&ID 圖面轉成主檔（可後做；開站須人工確認結構化欄位）
- 對應表對該製程全部設備×全部化學品做排列組合（只記實際存在之關係）

## 4. 硬檢核（失敗則拒絕存檔或拒絕「評估完成」）

1. 細表不得自由輸入設備名、品名、課室名；只能選 ID（含 SDS 代號）。禁止在 Chemical 存 SDS 檔。
2. Equipment 無 process_id 或 maint_dept_id → 不得存。
3. Department／Process 未建完 → 不得開風險評分。
4. Assessment 無 process_id → 不得開 Node 的設備／chemical_code 欄。
5. Node.equipment_id 的 Equipment.process_id 必須等於該 Node 的 process_id。
6. Node.chemical_code 必須存在 Chemical(chemical_code, 該 process_id)。
7. Safeguard 純文字 → 未完成。
8. EsdScenarioAction 的 equipment.process_id 必須等於 scenario.process_id。
9. esd_equipment_id 的 equipment_type 必須是緊急停車系統。
10. PidDrawing 涵蓋之 equipment_id 必須存在；HAZOP 用圖之 process_id、drawing_no、revision 必須等於現況 as-built 登錄。
11. 改善關閉：已指明主檔列 + 主檔已更新 + 節點已重評或合格人員記載無須重評。只勾「已改善」不得關。
12. 過境未接製程、未裝卸 → 不建核心資料表、不評分。
13. ChemicalSdsLink：三方 chemical_code 必須相同；sds_id 必須存在；Chemical 列必須已存在。chemical_code 不符 → 拒絕存檔。
14. Chemical 無現況版 Link → 送審 2.2 及三種檢核不得標示完成。
15. ProcessEquipmentChemicalMap：Equipment.process_id 與 Chemical.process_id 必須等於列上 process_id；禁止為「該製程全部設備 × 全部化學品」一次生成。no_process_chemical＝true 與 chemical_code 不得同時有值。
16. 該製程每一筆 Equipment 至少一列對應表（有化學品或聲明無）之前，不得開放該製程「評估完成」或風險評分。
17. Node 所選 equipment_id／chemical_code 必須能對到對應表（或該設備之無製程化學品列）。
18. PromptEvent 不得寫入 RiskScore 的 S、L、等級；畫面預填 S／L 視為不合格。
19. 提示 status＝not_applicable 而無 na_reason → 拒絕把該列標為已處理。

## 5. 畫面順序（可合併步驟，不可顛倒）

1. Site（含勞工人數）  
2. Department；上傳組織系統圖  
3. SiteBasicDoc：計畫／規章／制度類附件（項次 3、5–11；項次 2 之危害通識計畫可與 Chemical 同一步）  
4. Process（operating_dept_id 選 Department）  
5. 廠區位置圖附件 + Area 結構化（控制室、消防、各區人數；2.12 之一、二由設備及化學品投影）  
6. Equipment（JOIN 顯示製程名、部門名；動力來源填 power_kind；勾選 is_regulated_machinery；有 ESD 則建 EsdScenario）  
7. SdsDocument → Chemical → ChemicalSdsLink（下拉僅該 chemical_code 已有之 SDS 代號；禁止在化學品列上傳孤檔）  
8. ProcessEquipmentChemicalMap（對應表）：只新增實際關係；帶入 h_codes、material；勾 may_remain；人員填 review_notes 或確認／不適用。本步觸發 §10 寫死規則，產生 PromptEvent  
9. PidDrawing 附件 + 結構化 + 涵蓋設備  
10. 製程安全資訊其他掛載（存量、上下限、材料、釋壓、連鎖；材料須與對應表一致）  
11. 化學品三種檢核（引用 Chemical）；不相容以對應表 review_notes 為準，不另建相容性總表  
12. Assessment：先選 process_id，下拉只出來自對應表的設備與 chemical_code；進入節點列出 stage＝pha 之 PromptEvent；S、L 空白由小組點選；改善  
13. 機械完整性頁：分類清單與 Equipment 同一編號；列出 stage＝mi 之 PromptEvent；不連劣化庫、不算裂化速度  
14. 事故納入、設置地點（area_code）、人為因素、控制失效  
15. 其餘單元；計畫已於步驟 3 上傳者註明參閱；無則聲明  

設備下拉（HAZOP）：對應表中該 process_id 的 equipment_id（含 no_process_chemical 列），再 JOIN Equipment。禁止只按 `Equipment.process_id` 列出卻略過對應表。  
化學品下拉（HAZOP）：對應表中該 process_id、該節點設備之 chemical_code。  
涵蓋檢查：該製程 Equipment 未出現在任何 Node 者列出（可依 phase_class、equipment_type 篩）。

## 6. 風險讀數 stale（同一套矩陣再評，禁止另開脫鉤風險表）

設 stale＝true 當：

- 變更改了 Process／Equipment／Chemical 任一列  
- 現況 ChemicalSdsLink 改掛，或所連 SdsDocument 版次／附件變更  
- PSSR 發現影響安全缺失  
- 安全關鍵設備檢查逾期或缺陷未矯正仍操作  
- 事故／虛驚結案且與製程有關  
- 裝卸位新增 chemical_code 或運輸分類變更  
- 更換矩陣或可接受基準  
- 定期評估屆期  

系統列出掛在被改 PK 上的 Node／Consequence。是否停機由事業單位依法令決定，系統只提示。

改善關閉見 §4.11。

## 8. 給實作 AI 的驗收（最小）

- [ ] 無 process_id 的 Equipment 無法存檔  
- [ ] HAZOP 未選製程時設備欄 disabled  
- [ ] 選製程 A 後無法選製程 B 的設備  
- [ ] 設備表沒有「製程名稱」「部門名稱」實體欄  
- [ ] 部門改名，設備列不必逐筆改  
- [ ] P&ID 只上傳檔、未填 drawing_no／涵蓋設備時，HAZOP 不能勾該圖  
- [ ] 動力來源未填 泵浦／氣動 無法存檔  
- [ ] ESD 系統設備無方案或無動作清單時，該製程緊急停車標示不完備  
- [ ] 裝卸佔用寫車牌不新增 Equipment  
- [ ] 送審第二章計畫類（至少項次 3、8、9、10、11）有附件槽，未拆全文  
- [ ] 平面圖頁不另填設備名／品名；（一）（二）由 is_regulated_machinery 與 Chemical＋存量投影  
- [ ] 場所至少一處控制室區域或控制系統設備、一處消防標示  
- [ ] Chemical 表無 sds_file 欄；SDS 只在 SdsDocument  
- [ ] 代號表 chemical_code 與 SDS 庫 chemical_code 不符時無法存檔  
- [ ] 同一 SDS 代號可連同一 chemical_code 的多個製程列；無現況 Link 不得標示送審 2.2 完成  
- [ ] 對應表不能一鍵「全製程設備×全化學品」生成；未對應完的製程不能評分  
- [ ] HAZOP 選 P-TANK 選不到僅屬於 P-ACID 的 PL-201  
- [ ] 碳鋼＋7647-01-0＋may_remain＝true 時，PHA 與 MI 列出寫死提示，S／L 仍空白  
- [ ] 使用者把該提示標不適用且未填理由時，不得標為已處理  
- [ ] 畫面上無「附表一」…「附表十四」字樣；可用單元名稱與「附件一」
